FINANCIAL SIMULATOR: TECHNICAL SUMMARY FOR AI AGENTS
====================================================

PURPOSE
-------
This is a small Python personal-finance simulator with two entry points:
1. app.py: the primary Streamlit UI and its configuration/export helpers.
2. example.py: a standalone Python example using the model directly.

Outputs are illustrative, stochastic projections, not financial advice.

PURCHASE PROPERTY UI (ISSUE #82)
--------------------------------
The opt-in bordered panel in app.py builds PropertyPurchase for scheduled mode
(1-based UI month converted to zero-based engine month), or AutomaticPurchasePolicy
for first-eligible cash-triggered mode. Automatic eligibility requires Main cash
to meet both minimum_available_cash and down payment + fees + reserve. The panel
passes selected_rent_expense by exact name and exposes monthly_expenses/yearly_tax.
Automatic mode can also carry an optional MortgageAffordabilityPolicy. It selects
income sources by name; always excludes annual bonuses; applies an explicit
variable-income inclusion percentage to net regular income; combines active
existing loan payments with the proposed mortgage payment; enforces a
debt-service ratio and optional base,
adult, and dependent buffers; and stores the latest assessment/reason in
purchase_outcome. The proposed payment always comes from Loan and is added once.
This is an editable planning heuristic, not lender approval. None preserves the
legacy cash-only behavior. JSON import converts qualifying income names back to a
tuple and older automatic policies remain valid. A short-lived pre-merge
bonus-income field is ignored on import so it cannot weaken the conservative rule.
AutomaticPurchasePolicy.completion_delay optionally carries a
PurchaseCompletionDelayPolicy with inclusive minimum/maximum months and a retry
or cancel rule. Equal bounds are fixed and do not consume random state; unequal
bounds call the trajectory-seeded random source once at first eligibility. The
engine keeps rent and renter state unchanged while pending, rechecks cash and
mortgage affordability only when completion is due, and creates ownership state
only after a successful closing. purchase_outcome retains eligibility, initial
and next scheduled months, sampled delay, attempts, status, and actual month.
The preview calls Loan.monthly_repayment. Import restoration populates purchase
fields and selected rent; asdict export preserves optional fields and legacy
exports omit them. Results report purchased trajectory count/share and actual
month range, or no purchase. The existing engine records purchase_outcome and
purchase_events and applies the #81 rent transition. The UI normalizes scheduled
purchase_events into the same outcome display shape as automatic purchases,
clears purchase widget keys during import, and clamps scheduled months to the
current horizon. Regression coverage verifies outcome normalization.


FAST START
----------
Install:  python3 -m venv .venv && .venv/bin/python -m pip install -r requirements-dev.txt
Test:     .venv/bin/python -m pytest -q        (or: make test)
Run UI:   python3 -m streamlit run app.py  (or: make run)

Runtime dependencies are in requirements.txt; pytest is added by
requirements-dev.txt. There is no package/build system, database, API service,
or JavaScript source tree. Modules are imported directly from the repo root.


FILE MAP
--------
app.py
  Streamlit UI; scenario dataclasses; model construction; single/multi-run
  orchestration; chart events; month drill-down; JSON import/export.

financial_assumptions.py
  Authoritative validated defaults for investment returns/volatility, stock
  dividends, contribution fees, and income tax rates. The UI and domain models
  consume this module; do not duplicate these defaults elsewhere.

utils.py
  Core month-by-month simulation loop and net-worth calculation. This is the
  main engine used by both app.py and example.py.

bank_account.py
  Cash account, deposits/withdrawals, annual account fee, and
  InsufficientFundsException.

income_source.py
  Income types, taxation, annual growth, bonuses, freelance variability, and
  stochastic salary raises/promotions.

expense.py
  Recurring Expense, age-dependent AgeBasedExpense, and annual YearlyExpense.

investment.py
  Stock, real-estate, bond, and safe investments with stochastic annual returns,
  monthly compounding, stock dividends, explicit contributions, per-investment
  automatic contribution settings, and contribution fees.

property_purchase.py
  Validated atomic property purchases and the optional cash-triggered purchase
  policy plus optional mortgage-affordability and completion-delay policies.
  Purchases create the property investment, pay down payment and fees, derive
  mortgage principal, and emit accounting events for the simulation.

scenario_workspace.py
  Defensive named configuration snapshots for the optional A/B workspace.
  ScenarioVariant never exposes its stored mutable config; ScenarioWorkspace
  returns new workspaces for save, rename, activate, and reset operations.

loan.py
  Fixed-payment amortization and optional fixed-interest behavior.

plots.py
  Standalone Matplotlib charts. Preserve these when changing the Streamlit
  Altair/Vega-Lite chart; the Python chart supports dashed loan-event lines.

tests/
  Pytest unit, integration, family-scenario, and subprocess example coverage.

README.md
  User-facing setup and current UI behavior. documentation.md is older and may
  not reflect recent implementation details.


CONFIGURATION AND OBJECT CONSTRUCTION
-------------------------------------
app.py and financial_assumptions.py define these dataclasses:
  SimulationConfig, InvestmentConfig, IncomeConfig, ExpenseConfig, LoanConfig,
  DependentConfig, FinancialAssumptions.

build_components(config) converts them into fresh model objects and returns:
  (BankAccount, investments, loans, incomes, expenses)
This order intentionally matches compute_net_worth_over_time(years, ...).

Collection semantics matter:
  - None uses the legacy single-item defaults in SimulationConfig.
  - [] explicitly means no items.
Do not replace an explicit empty list with defaults.

Real estate is special:
  - monthly_contribution is forced to zero;
  - initial_amount is the full market value; ownership_percentage (default 100)
    determines the owned value included in investment totals and net worth;
  - linked_loan_name optionally identifies exactly one configured loan;
    liability_share_percentage controls how much of its remaining balance is
    attributable property debt (loan payments remain the user's full cashflow);
  - rental_income_name optionally identifies exactly one rent IncomeConfig and is
    copied into property reporting without another deposit;
  - monthly_expenses becomes a linked housing Expense;
  - yearly_tax becomes a linked YearlyExpense;
  - linked costs are displayed read-only under Expenses and edited under the
    real-estate investment;
  - annual property tax is charged in months 12, 24, ... and then inflated by
    the housing rate for the next year.

property_jurisdiction.py owns PropertyJurisdictionProfile and the pure
estimate_property_costs() conversion. Profiles contain editable percentage
estimates for acquisition costs, annual property tax, annual maintenance, and
rental operating costs. Value-based recurring estimates use the owned starting
value; acquisition costs use full purchase price; rental expenses use the linked
gross rent already attributable to the user. app.py resolves these estimates to
ordinary dollar costs before simulation and adds explicit fixed amounts once.
Core accounting classes do not contain country branches. No selected profile is
the legacy behavior. The two UI defaults are explicitly fictional. Estimates do
not dynamically reassess with property value or model real tax/legal rules.

utils.py emits stable property_market_values, property_owned_values,
property_debt_balances, property_equity, property_rental_income, and
property_operating_costs series. Equity is owned value minus the configured
attributable share of the linked-loan balance. These property series are
drill-down/reconciliation outputs only:
total_investment_value uses owned value, global loans are subtracted once by
get_net_worth, and linked income/expenses retain their original single cash
transactions. A loan or rent income can link to at most one property. Joint
cashflow allocation, property sale, and refinancing are not modeled. Rental
income and operating-cost inputs are already-attributable user
cashflows and are not scaled by ownership_percentage. Purchased properties are
100% owned and link their created mortgage.

Property purchases are opt-in and validated before mutation. A purchase records
the property at nominal price, expenses transaction fees, derives mortgage
principal as price minus down payment, and starts mortgage repayment in the
following month. A scheduled recurring rent expense can end at the purchase
month; linked property expenses and annual tax then continue under the property
investment. Automatic purchases additionally require the configured available
cash threshold and minimum reserve and can happen at most once per trajectory.
Eligibility is evaluated after monthly obligations and cash sweeps at the
closing point. Insufficient cash is a normal deferred/no-purchase outcome, not
a simulation error; fixed-date purchases remain mandatory and may fail. The
reserve is a point-in-time minimum immediately after closing, not a protected
subaccount. Purchase outcomes record it alongside actual post-closing cash;
later modeled cash flows can reduce that balance.

AutomaticPurchasePolicy.mortgage_affordability is optional. When present,
utils.py evaluates it every month using that month's pre-step regular income
rates and the current active-loan schedules. The result contains qualifying
income, existing and proposed payments, total debt service, ratio/limit, living
buffer, residual income, eligibility, and a readable reason. Missing or zero
qualifying income uses a null ratio (never Infinity) so JSON remains portable.
Both cash and mortgage tests must pass before closing.

When completion_delay is present, first eligibility samples or selects the delay
and records a pending closing without mutating renter/owner state. At the due
month, both checks run again. retry schedules the following month after failure;
cancel ends the attempt. A scheduled/retried month outside the horizon records
not_completed_before_simulation_end. None and fixed zero retain immediate closing.

Automatic cash-sweep contributions are configured per investment and supported
only for stock and safe types. They default to disabled. Each enabled investment
has a cash threshold, percentage of current cash, and yearly limit. The legacy
expense guard (cumulative yearly expenses below 80% of cumulative net income)
is fixed rather than user-configurable. Eligible investments are processed in
list/UI order, so earlier sweeps reduce cash available to later investments.

Dependents become AgeBasedExpense objects. At the configured school-start age,
school_monthly_cost is added to the base monthly cost.


SIMULATION FLOW
---------------
run_simulation(config) builds fresh components and runs one seeded scenario.
run_simulations(config, count) runs seeds config.seed + 0..count-1 and returns
the month-by-month arithmetic mean. run_simulation_batch(config, count) also
retains every SimulationTrajectory with its effective seed and complete monthly
details. The Streamlit Monte Carlo section defaults to an Overview of arithmetic
averages, which is not a guaranteed or individually realizable household path;
averaged cash/net worth can conceal liquidity shortfalls in individual runs. The
Individual run view shows one retained path and its seed. Quantitative downside
metrics and uncertainty shading are intentionally deferred to issues #25 and #67.

compute_net_worth_over_time() processes each simulated month in this order:
  1. Receive each income after tax.
  2. Pay each expense.
  3. Pay each active loan and record its first repayment-completion month.
  4. Advance investments, receive stock dividends, and make contributions.
  5. In each year's month 12, apply the bank's annual fee.
  6. Apply any enabled per-investment automatic contribution policies in list
     order, recording gross transfers and fees separately.
  7. Store ending detailed balances and flows after all monthly transactions.
  8. Calculate net worth = cash + investments - remaining loan balances.

tests/test_accounting_invariants.py reconciles every monthly cash delta,
investment transfer/fee movement, and liability balance using deterministic
fixtures. It also compares complete outputs from equivalent real-model scenarios
with a fixed seed. Preserve these invariants and the documented transaction order.

Withdrawals for expenses, loans, and automatic stock contributions use the
cash account. An unaffordable required expense/loan raises
InsufficientFundsException with the month, obligation, and available cash.

Seeded runs save and restore Python's global random state. Preserve this
isolation when adding stochastic behavior.


ANNUAL ADJUSTMENTS AND STOCHASTIC RULES
---------------------------------------
IncomeSource.step():
  - Returns income after tax.
  - Regular income grows after every 12th month, affecting month 13 onward.
  - Salary growth is 2% yearly; other growth rates are in income_growth.
  - Salaries can also receive stochastic raises/promotions at year-end.
  - A configured bonus is paid in the 12th month of a year before tax.
  - Freelance income may be zero or half in a month.

Expense.step():
  - Regular expenses inflate after every 12th month, affecting month 13 onward.
  - Rates vary by expense type and live in expense_growth.
  - "unexpected" expenses occur stochastically rather than monthly.

Investment.step() / add_contribution():
  - Uses a Gaussian annual return by investment type, compounded monthly.
  - Chooses a new annual rate every 12 months.
  - Stocks pay modeled dividends quarterly.
  - Contributions to stock/bond/safe investments incur a fee of up to $50;
    add_contribution() returns the charged fee.
  - Automatic policies are supported only for stock/safe and default off.


RESULT SHAPE
------------
compute_net_worth_over_time() and run_simulation() return:
  (monthly_net_worth, loan_repayment_dates, monthly_details)

loan_repayment_dates maps loan name -> zero-based month index.

monthly_details contains:
  investments       list: aggregate ending investment value by month
  bank_account      list: ending main cash balance by month
  investment_values dict: named investment -> monthly values
  automatic_contributions dict: named investment -> gross automatic transfers
  automatic_contribution_fees dict: named investment -> associated fees
  income_rates      dict: named income -> regular gross monthly rate used
  income_values     dict: named income -> actual net amount received
  expense_values    dict: named expense -> amount paid
  loan_balances     dict: named loan -> remaining balance
  loan_payments     dict: named loan -> amount paid

Most UI event/month labels are one-based. The engine's current_month and loan
repayment indices are zero-based; build_simulation_events() performs conversion.


STREAMLIT UI AND EXPORTS
------------------------
main() owns Streamlit session state. Sidebar categories are independent
expanders with collapsed summaries. The simulation count and run button live in
the main area. Large money inputs intentionally discard cents via _whole_amount.

The result chart is Altair/Vega-Lite and includes net worth, cash, investments,
legends, pan/zoom, click-to-select month, and dashed event lines for loan payoff
and school start. A fresh run selects the final month by default. Selected-month
tables come from get_month_details() and include named balances, gross regular
income rates, actual net income, expenses, loan payments, and itemized automatic
investment contributions/fees.

create_simulation_export() writes schema_version 1 JSON with parameters, summary,
monthly results, repayment dates, and chart events. read_simulation_export()
validates and restores parameters only. The import action sets a one-shot session
flag so the next Streamlit rerun automatically simulates the restored scenario.
It also migrates old real-estate exports by treating legacy
monthly_contribution as monthly_expenses. Exports without the automatic-policy
feature marker import with all automatic policies disabled and surface a safety
warning. Keep old schema files readable or explicitly version a breaking format
change.

The opt-in A/B workspace stores exactly Baseline A and Alternative B in v1. On
each rerun app.py saves the visible SimulationConfig only into the active variant;
Streamlit callbacks load a target config before keyed sidebar widgets are
instantiated. Switching or resetting an active variant clears simulation_result,
so results cannot leak between scenarios. create_scenario_workspace_export()
writes a separate parameters-only `financial-simulator-scenario-workspace`
schema; each embedded scenario uses the established single-scenario parameter
document and reader. Existing single-scenario JSON is unchanged. This slice does
not run paired scenarios or calculate deltas; issue #31 owns paired seeds and the
comparison dashboard.

Monthly export rows contain a property_positions mapping with market value,
owned value, attributable debt, equity, rental income, and operating costs.
InvestmentConfig exports preserve ownership_percentage, linked_loan_name,
liability_share_percentage, rental_income_name, and jurisdiction_profile_name;
legacy files receive 100%, None, 100%, None, and None respectively. Scenario
exports also preserve the editable jurisdiction_profiles collection and the
future-purchase profile assignment; legacy files default both to empty/unset.

Financial assumptions are stored under parameters.assumptions and marked by
features.financial_assumptions version 1. Missing assumptions in older exports
resolve to the historical defaults; explicit zero values are preserved. The UI
edits them in a dedicated sidebar expander, and FinancialAssumptions validates
finite values, exact mapping keys, bounded rates, and nonnegative fees.
Property-purchase exports preserve fixed or automatic purchase configuration,
purchase events, fees, and purchase outcome details.
Completed purchase events appear in the interactive chart as a distinct labeled
vertical dashed line; no-purchase outcomes do not manufacture an event marker.
The averaged Overview groups per-trajectory purchases by month and labels their
earliest/latest range with one rounded-midpoint marker rather than copying
trajectory 1 or drawing every run. Its chart label is deliberately compact;
tooltip/caption text retains the range and count. Individual run shows the exact event.


TESTING AND CHANGE CHECKLIST
----------------------------
Primary command: .venv/bin/python -m pytest -q (after the Fast Start setup; use a unique writable
--basetemp when needed; tests run in an isolated Python 3 virtual environment).

Pytest is configured in pytest.ini to use the repository-local .pytest-tmp
directory for its base temporary directory. The root conftest also falls back
to that directory when a runner supplies an unusable --basetemp, such as a
read-only /tmp path. A supplied --basetemp remains in effect when its parent
is writable.

Before changing behavior:
  - Add/update tests in tests/test_app.py for app/config/result behavior.
  - Use tests/test_family_scenarios.py for dependent-age scenarios.
  - Use tests/test_bank_account.py or tests/test_utils.py for engine mechanics.
  - Keep tests/test_end_to_end.py and example.py working.

For Streamlit UI changes, also run a smoke test with
streamlit.testing.v1.AppTest: load app.py, assert no exceptions, run a
simulation, assert no exceptions again, and inspect relevant widgets/tables.

When adding a monthly detail field, update all of:
  1. utils.py monthly_details initialization and per-month append logic;
  2. app.py run_simulations() averaging;
  3. get_month_details() if it should appear in the UI;
  4. create_simulation_export() if it belongs in saved results;
  5. tests for one run, averaged runs, detail rows, and export as appropriate.

When adding a scenario input, update its dataclass, build_components(), session
state defaults/migration, import restoration, sidebar editor/summary, export
round trip, and tests.


IMPORTANT INVARIANTS / GOTCHAS
------------------------------
  - Item names are dictionary keys in monthly details; unique names are safest.
  - Engine repayment dates are zero-based; UI/export months are one-based.
  - Annual adjustments happen after calculating month 12, so new regular rates
    normally first apply in month 13.
  - Monthly cash and investment snapshots are recorded after automatic
    transfers and must reconcile with that month's net worth and loan balances.
  - Automatic contributions are opt-in heuristics, not optimization advice;
    list order matters when multiple policies are enabled.
  - YearlyExpense is paid in month 12, not divided across months.
  - UI major-money inputs display whole dollars by design.
  - Multi-run Overview results are arithmetic averages, not realizable paths;
    keep the interpretation warning and "Average" wording in metrics/details.
  - Do not remove or replace plots.py merely because the Streamlit chart is
    interactive.
  - This is exploratory software; preserve the financial-advice disclaimer.
